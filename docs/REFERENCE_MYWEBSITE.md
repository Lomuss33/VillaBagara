## How to learn for an actual task

1. Define the guest-visible result and reproduce Villa's current behavior. Examples: reach Contact by keyboard, download a smaller thumbnail, or keep an input above the mobile keyboard.
2. Find the reference feature through its `AGENTS.md`, `MAINTANER.md`, `docs/README.md` feature index, and relevant architecture page. Source and the lockfile decide what is implemented; archived plans supply history.
3. Trace one complete path: JSON field -> parser/wrapper -> component -> owning SCSS -> provider/utility -> relevant test. Include imports and generated assets. A JSON setting needs both normalization and a renderer that consumes it.
4. Compare Villa's corresponding owners. Separate portable behavior from personal content, route-specific branches, styling assumptions, generated files, and dependencies. Use scoped diffs/history. Recheck current files before editing when another task has advanced the tree.
5. Implement the smallest complete adaptation. Preserve Villa's content, locales, stable IDs, public path resolution, and visual identity. Introduce reusable options when the guest feature needs them.
6. Verify the affected interaction and update its guidance and [STATE.md](STATE.md). Distinguish observed results, source review, and proposed acceptance criteria. A reference build does not verify the adapted code.

Search unfamiliar descriptions by purpose and owner: “room presentation” -> feature blocks; “phone menu” -> viewport/navigation; “stuck photo” -> image lifecycle; “slow start” -> images/article loading; “page after returning” -> lifecycle/location. Add an alias when a real task demonstrates the need.

## Compatibility details that matter

- Locked versions: Villa uses React `18.3.1`, Vite `6.4.4`, Swiper `12.2.0`, React plugin `4.4.1`; the reference uses React `19.3.0`, Vite `8.3.2`, Swiper `14.3.0`, plugin `6.1.1`. Its README still says React 18: that statement is stale. Assess each port's API/build compatibility separately from dependency upgrades.
- `three`, `motion`, `matter-js`, `leaflet`, `qrcode`, and `@chenglou/pretext` belong to concrete reference features. Image generation uses `sharp` as development tooling. Inspect import chains before selecting dependencies.
- Reference Home is `#about`; Villa's is `#home`. Reference `SectionBody` changes Home/Experience article order in code. Preserve Villa's registry order and section IDs.
- Villa owns `ArticleGalleryWall`, `FloatingContactButton`, `StartupScreen`, and `VillaBagaraLoaderScene`; corresponding paths are absent from the reference. Replacing its registry/shell would remove active Villa behavior.
- Villa's static checker and article scaffolder parse the literal `SectionBody.ARTICLES` object. A lazy registry refactor must update both tools, the renderer, and its Suspense owner.
- Reference item wrappers honor explicit item IDs and multiple categories; Villa assigns wrapper item IDs by position and supports one category. Trace article IDs through the parser too. Coordinate identity changes with React keys and stored component state.
- Reference `imgAlt` is an alternate image source; the `imageAlt` getter produces accessibility text. Inspect usage before transferring unfamiliar fields.
- The reference generator has a source-directory allowlist and creates `public/images/__responsive/` and `src/data/generated/imageManifest.generated.js`. Adapt it to Villa's `images/villa_bagara/` sources; author sources and regenerate outputs.
- Reference `npm run dev`/`build` invoke résumé/CV preparation; its workflow publishes a custom-domain `gh-pages` site. Villa's prepared workflow uses official Pages artifacts under `/VillaBagara/`. Adopt checks within [Villa's deployment contract](DEPLOYMENT.md).
- The review initially found a 3,495,768-byte estate PNG. Current active JSON uses `front-porch.webp`, 517,906 bytes; the PNG remains for social metadata. Recheck source before acting on an earlier measurement. Existing size budgets are authoritative for subsequent work.

## Prepared improvement sequence

Publication remains the next delivery step in [PLAN.md](PLAN.md). This review prepares the following engineering candidates.

1. **Named, keyboard-reachable navigation/tools.** Start in `GestureAwareButton`, desktop/mobile navigation, and language/theme tools. Sampled Villa collapsed desktop links exposed empty accessible names: labels use `display: none`, and `data-tooltip` supplies no accessible name. Several actions use anchors without `href`; the shared control declares `disabled` without applying native disabled behavior. Adapt semantic controls and label forwarding; check compact/expanded navigation, Tab/Enter/Space, focus, active state, and four locales. Retain real hash links.
2. **Measure responsive estate thumbnails.** The current WebP optimization is complete. Use it as the baseline, inspect rendered thumbnail sizes/transfers, then add derivatives/manifest only if worthwhile. Acceptance: comparable visuals, smaller measured transfers, correct `/VillaBagara/` candidates, cached/source-change reliability, and working full-resolution gallery viewing.
3. **Viewport/lifecycle reliability.** Adapt viewport offsets, overlay cleanup, bounded transition timers, and pause/resume behavior within the existing shell. Keep the current layout boundary initially. Acceptance: resizing agrees with navigation; contact inputs stay reachable; scrolling survives modal dismissal and page return; reduced motion works.
4. **Guest content capabilities.** Build a reusable photo/text feature block for Stay or Services. Consider filters, location/directions, or restrained landscape decoration when there is concrete content. Acceptance: translations wrap, cards reflow, keyboard/touch work, both themes remain readable, and performance stays within the current policy.

Use lazy loading when measurement or a newly added feature justifies it. CV exports, name interactions, artist players, games, elaborate comparison maps, and WebGL artwork provide mechanics to study; adoption needs a guest-facing purpose.
